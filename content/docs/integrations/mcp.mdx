`@interven/mcp-guard` is an MCP server that scans every `tools/call` through
Interven before it executes. Drop it into your MCP client configuration and
every tool call gets policy + risk evaluation.

## Install

```bash
npm install -g @interven/mcp-guard
```

Or run directly:

```bash
npx @interven/mcp-guard
```

## Configure with Claude Desktop

Add to your `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "interven-guard": {
      "command": "npx",
      "args": ["@interven/mcp-guard"],
      "env": {
        "INTERVEN_API_KEY": "iv_live_YOUR_KEY"
      }
    }
  }
}
```

## Configure with Cursor / Cline

Same pattern — add the MCP server to your IDE's MCP configuration with the
`INTERVEN_API_KEY` environment variable.

## Proxy Mode

For full interception of an existing MCP server's tool calls, use proxy mode:

```bash
npx @interven/mcp-guard proxy -- npx @your-org/your-mcp-server
```

This spawns your MCP server as a child process and intercepts every `tools/call`
JSON-RPC message. The agent sees the same tools, but each call is scanned
before execution.

```json
{
  "mcpServers": {
    "guarded-server": {
      "command": "npx",
      "args": ["@interven/mcp-guard", "proxy", "--", "npx", "@your-org/your-mcp-server"],
      "env": {
        "INTERVEN_API_KEY": "iv_live_YOUR_KEY"
      }
    }
  }
}
```

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `INTERVEN_API_KEY` | — | API key (required) |
| `INTERVEN_GATEWAY_URL` | `https://api.intervensecurity.com` | Cloud endpoint |
| `INTERVEN_FAIL_OPEN` | `0` | Set to `1` to forward on scan error |

## Exposed MCP Tools

The guard exposes two tools to the LLM:

- **`interven_scan`** — manually scan a tool call before execution
- **`interven_scan_response`** — scan a response body for exfiltration correlation

## Exposed MCP Resources

- **`interven://about`** — context about Interven for the LLM to understand the guard

## Decisions

| Decision | MCP behavior |
|----------|-------------|
| **ALLOW** | Tool call proceeds normally |
| **DENY** | Returns error content with reason codes |
| **SANITIZE** | Rewrites tool arguments with redacted values |
| **REQUIRE_APPROVAL** | Returns message with approval ID; blocks until approved |

## Alternative: downstream-proxy mode (B7)

If your agent is already configured to talk to a third-party MCP server
(postmark-mcp, Slack-MCP, internal MCP servers, etc.), you can have
Interven sit transparently between the agent and that server — every
`tools/list` runs through the **B7 inspector** (8 detection signals
covering tool drift, set drift, prompt injection, semantic drift,
capability mismatch, origin tampering, risky parameter injection), and
every `tools/call` is **policy-gated** with the inspector's reason codes
available to your policy DSL via `mcp_*` operators.

See the [dedicated MCP downstream-proxy guide](./mcp-proxy) for
the full setup, including the ML sidecar for semantic-drift and
prompt-injection-classifier signals.

Pick the right mode:

| You want… | Use |
|-----------|-----|
| Quick-start: gate ANY tool an MCP client offers (Claude Desktop, Cursor) | `@interven/mcp-guard` (above) |
| Protect a SPECIFIC downstream MCP server with deep inspection + drift detection | [downstream-proxy mode](./mcp-proxy) |
